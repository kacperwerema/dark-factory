# Which test packages `make test` may take from go test's cache
# (tools/test-shards -cache-list; format: internal/testshard.CacheList).
# go test's cache reruns a package when its code, an environment variable
# it reads or a file it opens changes. A test whose answer comes from
# somewhere else (a git command about this checkout, this machine's memory
# or processes, the live board) would pass from the cache when it should
# fail, so its package goes on a fresh line, with the reason, and runs with
# -count=1 every time. A test that copies its inputs with os.ReadFile, and
# runs git only in its own temp repo, can be cached.
#
#   cached ./internal/x
#   fresh ./internal/y <why it must always run>
#   fresh-test ./internal/z TestName <why>   one test of a cached package
#
# A fresh-test test also runs on its own with -count=1 beside the cached
# run, so its package can stay cached. Every test package is listed once,
# every fresh-test names a test that exists
# (TestEveryTestPackageIsInTheCacheList, tools/test-shards). A test that
# reads the live board (liveboard.Dir) skips in the cached run when a
# fresh-test line names it and fails there when none does. make test
# TEST_CACHE=0 runs everything with -count=1; local CI's slow tier does.
