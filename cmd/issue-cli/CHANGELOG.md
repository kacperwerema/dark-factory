# Changelog

Release history for the `issue-viewer` web app and the `issue-cli` CLI.
GitHub releases on `michal-franc/ai-workflow-engine` are the source
of truth for release notes; `issue-cli process changes` fetches them live
and falls back to this embedded file when the API is unreachable. Keep
entries here mirrored with the GitHub release descriptions.

Lives at `cmd/issue-cli/CHANGELOG.md` (co-located with the CLI) because Go's
`//go:embed` cannot reference files outside the embedding package's directory.

Entries are newest-first. Each entry has the form:

    ## <version> — <YYYY-MM-DD>

    - user-visible change
    - another user-visible change

Shipped changes collect under `## Unreleased` at the top. A release is cut
per milestone (the `version:` on issues, see docs/roadmap.md): the lead
renames `## Unreleased` to `## vX.Y.Z — YYYY-MM-DD` and pushes, and the
release-marker Action tags and builds it. Pushes with `## Unreleased` on top
release nothing.

## v0.58.0 — 2026-10-31

- Security: the viewer now fails closed for any public request. A non-loopback Host, or any request that came through a proxy or tunnel, gets 403 unless `identity:` in projects.yaml is configured (Cloudflare Access team domain, AUD tag, owner emails) and the request's Access token verifies for an owner. **A LAN or VPN name under `allowed_hosts:` now needs `identity:` too.** See docs/API/security.md, which also has the go-public checklist and the route inventory
- Security: fixed several high and critical issues found in the pre-exposure review:
  - command injection through the agent name on dispatch routes;
  - writes outside the issues folder through issue create, which also no longer overwrites an existing issue;
  - frontmatter injection on create;
  - raw HTML and `javascript:` links in issue bodies;
  - an image upload that could be served as HTML;
  - shell quoting of paths and template values typed into shells;
  - git refs read from stats sidecars;
  - the `/page-raw/` CORS grant.

  Repros stay in the review issue
- Security: every answer carries nosniff, X-Frame-Options, Referrer-Policy and a base CSP (no framing by other sites). Request bodies are capped at 4 MiB, or 12 MiB for image uploads
- Security: `make security-check` attacks a throwaway loopback viewer as if it were public, then runs govulncheck. goldmark is upgraded to v1.7.17 (GO-2026-5320)

- **Outputs as documents: read a markdown output and comment on it.** A markdown output on the shelf opens in a reader (`/p/<project>/shelf/read/<id>`): the document set in the Workshop look with its contents, a Day / Night sheet, Raw file, and Approve / Reject. Select a passage, use 💬 on a heading, or write on the whole document: comments sit in the margin as threads with replies and Resolve, kept beside the file in `<issues>/.outputs/comments.jsonl`, and each lands on the output's issue as a `revise:` comment quoting the passage. `issue-cli output revise <id> --file` adds a version (back in review; the reader shows Changes since the last one and keeps each thread on its passage), `output comments <id>` lists the threads for the agent, `output reply` answers one. The shelf row shows `v2` and `💬 N open`. Only the owner's browser writes comments.
- **Anonymous usage sharing, on by default, and a collector to receive it.** Each install sends one names-only summary per day: command and flag names with counts, error classes, durations, bundled template names, workflow-feature ids, the number of projects, issues and departments, the version and OS. Never project names, slugs, paths, issue text or flag values. Nothing is sent while no collector URL is set, and the engine ships none yet. The first call says so once on stderr. Turn it off with `issue-cli telemetry share off` or `ISSUE_CLI_TELEMETRY=off`. `issue-cli telemetry sent` lists what was sent. `cmd/telemetry-collector` is a small receiver you can host yourself; it refuses anything that could carry free text. The viewer's `/telemetry` page draws its data (installs, versions, commands, features, workflows, error rates) once `telemetry_data:` in projects.yaml points at the collector's folder. What is sent, field by field: docs/CLI/telemetry.md, "Sharing usage" (factory/usage-telemetry-from-other-peoples-installs-opt-in-anonymous-and-a-view-for-the-owner).
- **HQ report: the company in a minute.** HQ's room on the company page links to a Report (`/p/<project>/hq/report`): one folded section per box (HQ, Product, each group and department in the company tree's order), whose headline says whether it is on track and what matters this week (goals moved, outputs to review, jobs due or missed, what is blocked and on whom, handoffs, spend against the budget). Opened, each section shows the detail behind it, a group's latest week report and the department lead's last `progress:` line. A department with nothing says so. It is derived from goals, the shelf, jobs, handoffs, open issues, spend and the newest health snapshot; no agent writes it. `/hq/report.md` and `issue-cli status --hq` give the same as text; the CEO's brief and `status.md` point at it (factory/hq-report-an-executive-summary-of-each-department-in-the-ceos-hq).
- **A group of departments has its own colour.** GTM's room on the company page, its building on the map, its crew column, shelf tab and connection lines are drawn in the group teal (`--group` in `static/workshop.css`) instead of the amber the GTM template wrote, which looked like HQ's yellow. Every group takes it, nested ones too, whatever `color:` projects.yaml sets; departments keep their own colour.
- **Evals per workflow: a workflow change gets a verdict for each workflow, with time and cost.** A workflow file declares `evals:`, saying per type how the factory benchmark scores a run: `tests` (hidden Go tests and checks, as before) or `output` (the run's output on the shelf, graded by promptfoo 0.124.1 through npx). Each output eval has `rubric:` lines graded by the benchmark's new `grader:` command, `assert:` items that need no model, and a `pass:` bar. The development and marketing templates come with evals (catalog entry `workflow-evals`), and lint check `evals` warns on a bad id, score, pass or type. A department's golden task comes only from an output the owner approved: `bench task add` copies the approved file as its reference and runs it on the department's own workflow file (`bench run --workflow <key>=<file>` replaces that file). Every task records wall time with scoring time, and tokens and cost (benchmark prices, then prices.yaml). `bench run` prints an estimate from the last run first. `bench compare` prints **By workflow (A → B)**: pass rate, score, wall, tokens and cost side by side, and net positive, net negative, no change or not comparable (+10% cost or +25% wall at the same quality is net negative). The worker and scorer get the sandbox's state and config dirs, and the scorer also gets its own HOME; the benchmark folder is hidden from both. Evals run only inside an owner-started `bench run`; nothing adopts by itself (factory/benchmarks-and-evals-for-every-agentic-workflow-is-a-workflow-change-a-net-positive-or-negative).
- **The company floor draws roads with work moving on them instead of typed lines.** One road per pair of rooms that pass work, routed like streets through the gaps between the rooms; roads that share a street merge. The open traffic moves along each road as small parcels in the sender's colour (● request, ▲ handoff, ■ output, ◆ dependency); with reduced motion they stand still and each road shows its counts. A red `!` sign marks traffic off the declared routes, and a declared road with no traffic is a thin dotted lane. Hovering or focusing a road names it under the floor, and clicking it opens the connections page. - **Sibling workers agree a format through `issue-cli ask` / `answer`.** An `ask:` comment on the sibling's issue shows at the bottom of that worker's next issue-cli call (`== Sibling asks ==`, with the `issue-cli answer` line), and the `answer:` comes back the same way on the asker's issue, once. `show`'s Depends on line marks `· ask open` / `· agreed` and suggests an ask for an open dependency. `issue-cli status` lists open asks under `## Open asks between siblings`. Comments only, no new transport; an ask or answer never approves a gate.

The old text stays in the comment's `edits` list with the time it was replaced; `show` marks the comment `(edited)`.

- **Local CI keeps a red run's log past the next green.** A re-run of the same head wrote `.ci/runs/<sha>.log` again, so a flaky failure's log was gone by the time anyone looked. A red run's log is now copied to `.ci/red/` (the last 10, at most 30 days, and the newest first red after a green past the count); `ci status` prints `Last red log: <path>`, the Status card shows a Last red log line and the red boxes in Last runs link to their kept log (`/p/<project>/ci/log/<name>`). The storage health family counts `.ci/` as `storage.ci_mb`.

Session keys (cmd/playtest/session.go, vocab.go) and everything else still need a bump or a trailer, and the guard that every source matches a tracked file now also fails on a source that matches only exempt files (cli/catalog-check-asks-for-catalog-na-on-test-only-and-fixture-only-changes).
- A playtest session written in design keeps its step ids: when in progress appends `## Test Plan` and the issue's session already uses `TP1`, `TP2`, …, the section starts with one box per such step and its own boxes number after them. An existing Test Plan is never renumbered.

- **`bench candidates --replay` replays each candidate before the owner picks it.** The filters looked sound but never ran anything: the benchmark-pack retro found tasks whose hidden tests needed main's merged-in code, tasks that didn't replay, and tests that already passed on base. `--replay [<slug>...]` replays each proposed candidate in a throwaway git worktree (temp dir, repo hooks off, removed and pruned after): base with the merged commit's hidden files must fail the hidden tests, base plus the branch's own commits (merges from main left out) must pass them. Each row gets `replay: solvable | needs later main | doesn't replay | tests pass on base | not checked — <why>`; `--json` adds `replay` and `replay_why`. One candidate at a time, `mem-guard check` before every `go test` (BLOCKED or 70% and up skips it as not checked). No model call, no benchmark file written; agents may run it.
