Lead flush for {{date}}, run {{period}} (previous flush: {{last_run}}).

The lead session should not live for days. You end today's: write the handoff the next lead starts from, tidy memory, close the lead. The close starts a fresh session of the same lead at once, and its first prompt carries your note, your summary, the memory pins, the state file and the tick to start again. Work through the steps in order.

1. **Read the day.** `issue-cli lead flush pack --run {{slug}}` prints the previous note, the commands that show the state, and the day's lead chat. Run those commands.
2. **Write the note** to a scratch file, then `issue-cli lead flush note --run {{slug}} --file <file>`. It has these sections only, `##` headings, 80 lines at most, and must stand on its own: Next (the ordered next steps; the Status page shows this list), Rules in force (the owner's words, only those a new lead would otherwise break), Released and installed (the newest release, the installed build). No State, Queue, Waiting on the owner or How to resume: the fresh lead's brief renders workers, the queue head and the owner's asks live from the state file, and the note command refuses a note that copies them. Facts every agent needs belong in memory, not here: `issue-cli memory add`.
3. **Write the summary** of the day's lead chat to a scratch file, then `issue-cli lead flush summary --run {{slug}} --file <file>`. 30 lines at most: what the owner asked and decided, in their words where it matters, and what was left open. It records what was said; it is not a place to decide anything.
4. **Tidy memory.** Read `issue-cli memory consolidate`. Near-duplicates: the same fact, merge with `issue-cli memory add "<one fact>" --scope <its scope> --supersedes <id>,<id>`; different facts, leave them. Stale: still true, leave it; no longer true, `issue-cli memory forget <id> --reason "<why>"`. Expired: leave it, or supersede it with what is true now. Proven ones: name them in your progress comment, file nothing. The lead's standing rules (lead scope, `issue-cli memory list --scope lead`) are yours to read, not to change: edit, forget and supersede refuse them. Name any that look stale, duplicated or contradicted by today in your progress comment, and the next lead tidies them.
5. **Close the lead.** `issue-cli lead flush close --run {{slug}}`. It closes the lead, stops its old tick and starts the lead again; if the start fails it says so, and you name the owner's command it prints in your progress comment. It refuses while the lead is in the middle of a turn: try again ten minutes later, twice. Still busy: leave the lead open and say so in your progress comment.
6. **Finish.** Post one `progress:` comment on this run with the note's path, the memory counts, the proven ones and whether the lead closed and started again. Tick the Chore box and move this run to done.

Rules for this run: start nothing (no dispatch, no job, no agent; close starts the lead again by itself), send nothing (no message to any agent, no comment on another issue), decide nothing (no approve, no decide, no pin, no queue change, no issue moved or filed but this one). Never delete a memory, never edit CLAUDE.md or any file in the repo, never write a secret. Stay off the lead's session except through step 5. Done when the note and summary are written, memory was looked at, the close was tried and the progress comment is posted.
